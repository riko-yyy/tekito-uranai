# テキトー占い(仮) 意思決定サマリー
 
## プロダクト方針
- 星占い風の順位ではなく「今日やってみる小さな行動」が主役
- 星評価・ラッキーカラーは補助情報として軽く添える程度
- 「結果をシェア」をメインアクションとして目立たせ、拡散を狙う
- 下部ナビは「今日の運勢」「履歴」「お気に入り/プレミアム」のシンプル3構成
 
## プラットフォーム
- **まずPWAで作る**。将来的にネイティブアプリ化(iOS/Android)する意図あり
- リマインド通知は「あれば良い」程度、必須機能ではない
- 通知が必須でないため、PWAで進める制約上のハードルは低い
 
## 技術選定（ネイティブ化を見据えて）
- **Reactで実装**（Vanilla JSではなく）。将来React Nativeへの移行、またはCapacitorでのラップを想定
- **占い抽選ロジックはUIから分離した純粋関数として実装**（1日1回制限の判定含む）。ネイティブ化時にロジックはそのまま移植できる設計にする
- データ構造はID・日付ベースの素直なJSON形式にしておく（将来サーバー同期しやすくするため）
 
## 履歴・パーソナライズ
- 要求レベルは「履歴の保存・閲覧ができること」（Lv.1）。行動傾向に応じた結果の出し分けなどは対象外
- **IndexedDBで端末内完結**。アカウント登録・ログイン不要
- お気に入りは履歴データに `isFavorite` フラグを立てるだけで実現（別テーブル不要）
- 制約：機種変更・ブラウザ変更・キャッシュ削除で履歴は消える（設定画面等に明記予定）
 
## バックエンド
- **現時点では不要**。静的JSON配信＋クライアント処理＋IndexedDBのみで完結（サーバーレス構成）
- バックエンドが必要になるタイミング：
  - クロスデバイスでの履歴同期
  - ログイン機能
  - プレミアム課金の状態管理（サーバー側検証が必要）
  - サーバー起点のプッシュ通知
  - アクションDBの運営側での随時更新配信
 
## MVP構成要素（確定）
1. アクションDB（`teki_uranai_actions.json`、100件、実装済み）
2. UI層（React、プロトタイプHTML/CSSを移植）
3. 占いロジック（抽選・重複判定の純粋関数）
4. IndexedDB（履歴・お気に入りの端末内保存）
5. 共有機能（Web Share API）
